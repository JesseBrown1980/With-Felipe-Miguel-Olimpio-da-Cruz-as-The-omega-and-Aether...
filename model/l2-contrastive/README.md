# asolaria-l2-contrastive

Integer-only Rust port of the trained Asolaria L2 ContrastiveGNN: the class in `contrastive_gnn.py`
(asolaria-behcs-256 `services/gnn-sidecar/models/`) with its run-1 checkpoint `contrastive_model.pt`
(sha256 `d371dbbf…`), the checkpoint `manifests/gnn_train_run1_results.json` names as `L2_ckpt`.
Crate `asolaria-l2-contrastive`, library `l2_contrastive`, no dependencies,
`#![forbid(unsafe_code)]`, Rust 1.81, no `f32`/`f64`.

**Lane.** `src/` is hot lane: integers only, in process, with no Python, torch, Node, JSON or HTTP.
`tools/` and the vendored upstream files are cold lane and run only in CI. Provenance, the evidence
for the forward, the upstream consumers and the measured agreement are in
[`PROVENANCE.md`](PROVENANCE.md).

## Modules

| Module | Port of | Public API |
|---|---|---|
| `weights` | `vendor/fnns/models/contrastive_model.pt` as Q24 integers (generated by `tools/quantize.py`) | `CONV1_W` ... `CLS2_B` |
| `model` | `ContrastiveGNN.forward` (contrastive_gnn.py:92-122) in eval mode, with the fallback `GCNConv` of contrastive_gnn.py:17-23 | `anomaly_probabilities`, `edge_outputs`, `edge_output`, `EdgeOutput`, `ModelError` |

- `anomaly_probabilities(x, edges)` is `forward(x, edge_index)`: `probs[:, 1]` per edge, Q24 in
  `0..=2^24` (contrastive_gnn.py:120-121).
- `edge_outputs(x, edges)` is `forward(x, edge_index, return_projections=True)`: per edge an
  `EdgeOutput { anomaly_q24, projection_q24 }`, the same `probs[:, 1]` and the 64-component
  `F.normalize(projection_head(edge_embeddings), p=2, dim=1)` in Q24 (contrastive_gnn.py:87-90, 116-118).
- `edge_output(source, target)` is `edge_outputs` on nodes `[source, target]`, edges `[[0, 1]]`.
- `x` is one `[i64; 6]` row of Q24 node features per node, `edges` the `(source, target)` pairs of
  `edge_index`. An edge naming a node `>= x.len()` gives `ModelError::NodeIndexOutOfRange` (torch
  raises IndexError there); no edges gives no outputs.

These are the outputs the class returns. The crate computes no score, threshold, weight or
composite from them; `PROVENANCE.md` lists every place upstream reads them.

## The forward, as the checkpoint was trained

The checkpoint's keys are `conv1.lin.weight`, `conv1.lin.bias`, `conv2.lin.weight`,
`conv2.lin.bias`, `edge_mlp.0.*`, `projection_head.{0,2}.*`, `classifier.{0,3}.*`, and its
`_metadata` lists the module paths `conv1`, `conv1.lin`, `conv2`, `conv2.lin` with no
`aggr_module`. That is the module tree of `ContrastiveGNN(6, 64)` built with the fallback `GCNConv`
of contrastive_gnn.py:17-23 (taken when `torch_geometric` does not import): a module holding one
`nn.Linear` named `lin`, whose `forward(x, edge_index)` returns `self.lin(x)`. The checkpoint loads
into that class strictly; built with torch_geometric 2.8.1 `GCNConv` the class expects `conv1.bias`
and `conv2.bias` and has no `conv*.lin.bias`. So `src/model.rs` runs, per node,
`Linear(6, 64)`, ReLU, `Linear(64, 64)` (dropout is off in eval); per edge,
`edge_mlp = Linear(128, 64)`, ReLU over `cat(h[source], h[target])`; then
`classifier = Linear(64, 32)`, ReLU, `Linear(32, 2)`, softmax, entry 1; and
`projection_head = Linear(64, 64)`, ReLU, `Linear(64, 64)`, then `F.normalize`.

Arithmetic is Q24 with i128 accumulation and one round-half-up per layer output. For two classes
`softmax(logits)[1]` is the sigmoid of `logits[1] - logits[0]`, taken from the exact Q48 difference
with a fixed-point sigmoid. It equals a 60-digit decimal reference on the 1,511 committed logits,
and next to a rounding tie it can be 1 unit away. `F.normalize` divides by `max(||v||, eps)` with
`eps` the float32 of `1e-12`, as torch/nn/functional.py:6126-6127 does. The integer version equals
an exact rational reference on 126 vectors, and at a half-unit tie in a vector whose largest Q48
component is above 2^51 it can be 1 unit away. `PROVENANCE.md` has the measurements.

## Agreement with torch

On the 262 edges of the fixture's layout graphs, `probs[:, 1]` is within 1 Q24 unit of torch and
every projection component within 8 (`tests/model.rs` allows 16). How close Rust stays depends on
input magnitude: `src/weights.rs` holds each float32 weight rounded to Q24, and the first layer
multiplies that rounding by the input. On the fixture's `mag` graphs, with features of both signs up
to 2^K, the largest differences for K = 4, 8, 12, 16, 20 are 1, 1, 1, 3, 11 units for
`probs[:, 1]` and 7, 7, 8, 80, 946 units for projections. The test allows 16 up to K = 8 and
16 * 2^(K - 8) above that. `PROVENANCE.md` has a larger sweep and a float64 comparison.

## Fixtures

| File | Written by | Content |
|---|---|---|
| `src/weights.rs` | `tools/quantize.py` (stdlib) | the checkpoint's 23,330 float32 weights as Q24, read without torch; refuses any other key list or module-path list |
| `tests/fixtures/expected-math.hbp` | `tools/math_referee.py` (stdlib) | `LN2_Q62`; 1,511 `SIGMOID` rows (decimal, 60 digits); 126 `NORMALIZE` rows (exact integer arithmetic) |
| `tests/fixtures/expected-model.hbp` | `tools/model_parity.py` (torch) | the `LAYOUT` row; 304 fixed-seed graphs, 755 edges (104 layout graphs with 262 edges, 200 `mag` graphs with 493 edges): Q24 inputs, float32 bits and Q24 of `probs[:, 1]`, and the 64 Q24 projection components per edge |

The graphs are SYNTHETIC, from fixed seeds. The layout graphs hold node features in the 6-feature
layout of train_baseline.py:31-38 and train_gslgnn_w9_3.py:224-231 with risk up to 21, 100 and
1,000,000, raw Q24 values in `[-2^26, 2^26)`, and four fixed graphs. The `mag<K>-<i>` graphs, 40
for each K in 4, 8, 12, 16, 20, hold float32-exact features of both signs up to 2^K. They show what
the code computes; they are not observed traffic. Every data file is HBP text; no JSON is read or
written.

## Checks

From `model/l2-contrastive/`:

```sh
sha256sum -c UPSTREAM.sha256                       # vendored bytes unchanged
cargo +1.81.0 clippy --locked --all-targets -- -D warnings
cargo +1.81.0 test --locked
python3 -I tools/quantize.py --check               # stdlib: regenerate in memory, diff
python3 -I tools/math_referee.py --check
<python with torch 2.14.1+cpu and torch_geometric 2.8.1> -I tools/model_parity.py --check
```

The torch check imports the vendored `contrastive_gnn.py` twice: once with torch_geometric present,
to record the key layout its `GCNConv` expects, and once with torch_geometric made unimportable, to
build the model the checkpoint was saved from. Before torch loads it sets
`ATEN_CPU_CAPABILITY=default`, `MKL_CBWR=COMPATIBLE`, `OMP_NUM_THREADS=1` and `MKL_NUM_THREADS=1`,
as model/l0-edge's tool does, so torch runs ATen's scalar kernels and oneMKL's single SSE2 code
path. It compares its output with the committed file byte for byte; see `PROVENANCE.md`.
