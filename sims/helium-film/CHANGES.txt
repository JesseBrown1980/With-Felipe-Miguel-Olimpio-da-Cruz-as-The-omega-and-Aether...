B1. HF-N02 cannot measure its top mode (2-unit records alias the n = 82 mode).
  Checked: period of n = 82 is in [2.2179, 2.2180] tu, below twice the 2-unit record interval; the alias
  |eps - pi| is in [0.30875, 0.30876] rad/tu (exact_extra.py).
  Choice: record every step (dt = 1/64), not every 1/4 tu. Reason, as corrected in the second pass (S-m1): per-step
  records can alias only a mode with eps dt >= sqrt6 (eps above 64 sqrt6 in [156.7673, 156.7674] rad/tu), and
  such an alias reads above 32 pi in [100.5309, 100.5310] rad/tu. So a planted fault that moves a frequency still
  shows as a miss. The first pass wrote that per-step records cannot alias any frequency the RK4 integrates
  stably (2 sqrt2/dt below pi/dt); that was false, because R(i sqrt6) = -1/2. At 1/4 tu (Nyquist 4 pi = 12.566) a
  fault that pushed a mode above 12.57 rad/tu would alias and could read inside the band. Per-step records give
  141.95 samples per period of the n = 82 mode (the first pass wrote 141.9).
  Changed: K57 (the exception and its reason); HFDEF method.gp; HF-N02 method (per-step records, the frequency
  rule pi (n_c - 1)/(t_last - t_first), linear interpolation between straddling steps); engine plan main.rs (one
  row per sign change, lossless for this method, about 400 rows per mode), run table, and a planted fault
  fault-n02-every-2tu.

  the frozen band P = 1876 with the 3 percent dx allowance needs 2 x 1.03 x 1876 + 32 = 3896.56 < 4096; 3400

  Cost: 45-65 min per 144,000 steps scales to [81.92, 118.33] min, "about 82 to 119 min plus about 20 min
