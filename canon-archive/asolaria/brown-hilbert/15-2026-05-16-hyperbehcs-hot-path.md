# Brown-Hilbert 15 - HyperBEHCS Hot Path

Status: ACTIVE_LOCAL_RULE
Date: 2026-05-16

Purpose: keep Asolaria/HyperBEHCS fast without destroying old evidence.

Law:

- Use `.hbp`, `.hbi`, SHA256, hex, tuple rows, and index pointers before JSON.
- JSON is cold compatibility, report, dashboard, debug, or archival output only.
- Do not hydrate large JSON when a hot packet, receipt, or source pointer answers.
- Preserve old heavy artifacts as cold provenance; do not erase them to make the new path look clean.
- Heavy artifacts may be deleted only after a working faster replacement exists, has receipts, benchmark proof, rollback, and a cold provenance pointer.
- Tuple width is not capped by habit. Width 50 is a parameter, not canon.
- Cube size and shape are tunable proof parameters. Smaller or different cubes are allowed only after benchmarked receipts.
- Promote geometry changes through PROF/supervisor review, white-room notes, and reversible ledgers.
- Hot packets may route candidates; final truth re-anchors to exact source path plus SHA256/hex receipt.
- Runtime authority does not come from compression. Execution still needs the normal authority gate.

Default action: plan with the hot path first, keep the cold path recoverable, replace before deleting, and record any tuple/cube geometry change as an experiment before promotion.
